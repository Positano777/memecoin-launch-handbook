# U - Users and community onboarding

Make the first useful community action independent of buying a token. Offer a reproducible bug report, documentation task, dataset correction, translation, or small fixture contribution. Explain which software is available now and how contributors can run it.

Publish the canonical mint in one maintained location and link that location from your profiles. Explain impersonation risks, support boundaries, and how administrators will communicate changes. Support should never request a recovery phrase or an unexplained wallet signature.

Create a moderation policy for paid promotions, conflicts of interest, compensation, harassment, and unsupported performance claims. State how contributors are credited and how any funded work is selected. An active issue tracker is more informative than a promise of future utilities.

**Deliverable:** a contributor quickstart and a public support/announcement policy. Link upstream licenses and original authors when sharing tools.
