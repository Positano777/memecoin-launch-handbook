# S - Security and incident response

Identify the people who can freeze communications, rotate infrastructure credentials, review treasury proposals, and correct a compromised canonical link. Keep an independent record of the official mint and communication channels.

If a private key or provider credential leaks, revoke/rotate what can be rotated and assess the permissions involved. A token program authority may need an on-chain change; a provider API key needs provider-side revocation. Do not ask users to sign a “recovery” transaction from an unverified emergency link.

For incorrect token configuration or an irreversible change, preserve the evidence and state what cannot be changed. Do not quietly replace a token address while continuing to market the original identity. Explain the remediation plan, any migration, and its risks before asking users to act.

**Deliverable:** [incident runbook](../templates/incident-runbook.md), rehearsed with a non-emergency example.
