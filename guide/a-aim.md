# A - Aim and audience

Write a one-paragraph reason for the project before selecting a ticker. Define the audience, the joke or cultural reference, the useful community activity, and what the token does not entitle its holder to. A token is not necessary for every open-source community; document why an ordinary donation page or grants program would not meet the same need.

Separate shipped software, funded work, and possible future work. If proceeds might fund maintenance, name the budget owner, reporting cadence, and what happens if funding is insufficient. Avoid turning a proposed feature into a promise of returns or a guaranteed delivery date.

**Deliverable:** a project brief with one audience, one purpose, a scope boundary, and a named maintainer. Use [the project brief](../templates/project-brief.md). **Exit check:** a newcomer can explain the project without referring to its expected token price.
